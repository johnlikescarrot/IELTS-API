# Contributing

Thank you for improving the IELTS API.

## Before opening a pull request

1. Keep the public, no-authentication contract intact.
2. Do not add official test papers, commercial books, recordings, answer keys, scraped text, or other material without clear permission for redistribution.
3. Add a source record, access date, and supported-claim list for each new reference fact.
4. Mark newly authored reusable prompts with an explicit content license.
5. Add focused tests for success and failure behavior, then run `npm run check`.
6. Keep the OpenAPI document, README, and route behavior aligned.

## Pull requests

Describe the user-facing change, data provenance, and validation performed. The Quality workflow runs formatting, linting, strict type checks, full coverage checks, and Super-Linter. Please resolve the checks before requesting review.

## Reporting issues

Do not include private candidate information or copyrighted test content in an issue. For content-rights concerns, open a minimal issue identifying the affected route or file without reproducing disputed material.
